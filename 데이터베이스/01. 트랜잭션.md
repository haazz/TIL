# 트랜잭션이란

- 데이터베이스의 상태를 바꾸는 하나의 논리적 작업 단위이다.
- 여러 쿼리를 묶어서, 전부 성공하거나 전부 실패(롤백)하도록 보장한다.
- 예: 계좌 이체에서 출금과 입금은 하나의 트랜잭션으로 묶여야 한다.

# ACID

- **Atomicity (원자성)** : 트랜잭션 내 작업은 전부 반영되거나 전부 취소된다. 일부만 적용되는 일은 없다.
- **Consistency (일관성)** : 트랜잭션 전후로 데이터가 무결성 제약(제약조건, 규칙)을 항상 만족한다.
- **Isolation (격리성)** : 동시에 실행되는 트랜잭션들이 서로 간섭하지 않는다.
- **Durability (지속성)** : 커밋된 결과는 시스템 장애가 발생해도 보존된다.

# 격리 수준 (Isolation Level)

- 동시성과 데이터 정합성 사이의 트레이드오프를 조절하는 단계이다. 낮을수록 동시성↑, 정합성↓.

1. **READ UNCOMMITTED** : 커밋 안 된 데이터도 읽음.
2. **READ COMMITTED** : 커밋된 데이터만 읽음.
3. **REPEATABLE READ** : 한 트랜잭션 내에서 같은 행을 여러 번 읽어도 같은 값. (MySQL InnoDB 기본값)
4. **SERIALIZABLE** : 완전히 순차 실행한 것처럼 격리. 가장 안전하지만 동시성 최저.

# 이상 현상 (격리 수준이 낮을 때 발생)

- **Dirty Read** : 아직 커밋되지 않은 데이터를 읽는 문제.
- **Non-Repeatable Read** : 같은 행을 두 번 읽었는데 그 사이 수정/커밋되어 값이 달라지는 문제.
- **Phantom Read** : 같은 조건으로 조회했는데 그 사이 행이 추가/삭제되어 결과 행 수가 달라지는 문제.

- 격리 수준이 높아질수록 이상 현상은 막을 수 있지만, 락 경합으로 동시성이 떨어진다.
