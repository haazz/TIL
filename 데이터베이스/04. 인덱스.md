# 인덱스 (Index)란

- 테이블의 데이터를 빠르게 찾기 위한 별도의 자료구조이다. 책의 색인(찾아보기)과 같다.
- 인덱스가 없으면 전체 행을 훑는 풀 스캔(O(n))을 해야 하지만, 인덱스가 있으면 정렬된 구조에서 빠르게 찾는다.

# 동작 원리 (B-Tree)

- 대부분의 RDBMS 인덱스는 **B-Tree(균형 트리)** 구조를 쓴다.
- 데이터가 정렬되어 있어 탐색·범위 검색을 **O(log n)**으로 처리한다.
- 등호(`=`), 범위(`<`, `>`, `BETWEEN`), 정렬(`ORDER BY`)에 효과적이다.

# 인덱스를 걸면 항상 빨라지는가? (단점)

- 항상 빨라지는 것은 아니며, 비용이 따른다.
- **쓰기 성능 저하** : INSERT/UPDATE/DELETE 시 인덱스도 함께 갱신해야 한다.
- **저장 공간 추가** : 인덱스도 디스크를 차지한다.
- **카디널리티가 낮은 컬럼**(예: 성별)엔 효과가 거의 없다.
- 함수 적용(`WHERE YEAR(col)=...`)이나 앞 와일드카드(`LIKE '%abc'`)는 인덱스를 못 탄다.

# 복합 인덱스

- 여러 컬럼을 묶은 인덱스이다. **컬럼 순서가 중요**하다.
- 앞 컬럼부터 차례로 조건이 걸려야 인덱스를 효율적으로 탄다. (왼쪽 접두사 규칙)

# 정리

- 읽기는 빨라지지만 쓰기·공간 비용이 든다.
- 조회가 잦고 카디널리티가 높은 컬럼에 선택적으로 건다.
- `EXPLAIN`으로 인덱스를 실제로 타는지 확인한다.
