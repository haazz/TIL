# 정규화 (Normalization)

- 데이터 중복을 제거하기 위해 테이블을 **분리**하는 작업이다.
- 데이터 무결성이 높아지고, 갱신 시 한 곳만 고치면 되므로 이상 현상이 줄어든다.
- 단점: 테이블이 나뉘므로 조회 시 **JOIN이 많아져** 읽기 성능이 떨어질 수 있다.

# 반정규화 (Denormalization)

- 조회 성능을 위해 의도적으로 중복을 허용하거나 테이블을 **합치는** 작업이다.
- JOIN을 줄여 읽기 속도를 높이고 DB 병목을 완화한다.
- 단점: 중복 데이터가 생기므로 갱신 시 모든 사본을 동기화해야 하는 부담이 생긴다.

# 자주 하는 오해

- "비정규화 = 테이블을 분리한다"는 설명은 틀리다. 분리는 정규화 쪽이다.
- 암기 포인트: **분리 = 정규화 / 합침·중복 허용 = 반정규화**

# 트레이드오프

- 정규화 : 무결성↑, 저장 효율↑, 읽기 시 JOIN 부담↑
- 반정규화 : 읽기 성능↑, 대신 중복·갱신 동기화 부담↑
- 보통 정규화로 설계한 뒤, 성능 병목이 명확한 지점에 한해 선택적으로 반정규화한다.
