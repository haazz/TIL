# N+1 문제란

- 연관 관계가 있는 엔티티를 조회할 때, 쿼리 1번으로 끝나야 할 일이 추가로 N번의 쿼리를 더 발생시키는 문제이다.
- 부모 엔티티 N건을 조회한 뒤, 각 부모의 연관 엔티티를 **지연 로딩(lazy loading)**으로 가져오면서 건당 쿼리가 1번씩 추가로 나간다.
- 결과적으로 `1(부모 조회) + N(자식 각각 조회)` 번의 쿼리가 실행된다.

# 흔한 오해

- "JOIN 때문에 1개 더 조회된다"는 설명은 틀리다.
- 원인은 JOIN이 아니라 **연관 엔티티를 건별로 따로 조회**하기 때문이다.

# 예시 (JPA)

```text
SELECT * FROM team;              -- 팀 10건 조회 (1번)
SELECT * FROM member WHERE team_id = 1;  -- 팀1의 멤버 (N번 중 1)
SELECT * FROM member WHERE team_id = 2;  -- 팀2의 멤버 ...
... 팀 수만큼 반복
```

# 해결 방법

- **Fetch Join** : JOIN으로 연관 엔티티를 한 번에 가져온다. (가장 일반적)
- **`@EntityGraph`** : 조회 시 함께 로딩할 연관을 명시한다.
- **batch size 설정** (`default_batch_fetch_size`) : 연관 조회를 `IN` 절로 묶어 N번을 몇 번으로 줄인다.

- 핵심은 "건별로 따로 조회하지 말고 한 번에 묶어서 가져온다"이다.
