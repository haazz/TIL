# 공통점

- 둘 다 객체의 모양(shape)을 정의할 수 있다.
- "interface는 객체용, type은 타입 지정용"이라는 구분은 부정확하다. 객체 정의는 둘 다 가능하다.

# interface

- 주로 객체나 클래스의 계약(contract)을 정의할 때 사용한다.
- `extends`로 상속이 가능하다.
- 선언 병합(declaration merging)을 지원한다. 같은 이름의 interface를 여러 번 선언하면 자동으로 합쳐진다.

```ts
interface User {
  name: string;
}
interface User {
  age: number; // 자동으로 병합되어 { name, age }가 된다
}
```

# type

- 타입에 별칭(alias)을 붙이는 문법이다.
- union(`A | B`), intersection(`A & B`), 튜플, 원시 타입 별칭 등 더 유연하다.
- 선언 병합은 지원하지 않는다. (같은 이름 재선언 시 에러)

```ts
type Status = "active" | "inactive"; // union은 type만 가능
type Point = { x: number; y: number };
```

# 선택 기준

- 객체/클래스의 모양은 `interface`를 쓰는 편이 관례이다. (확장성, 선언 병합)
- union·intersection·튜플 등 복합 타입은 `type`을 쓴다.
- 팀 컨벤션을 따르는 것이 가장 중요하다.
