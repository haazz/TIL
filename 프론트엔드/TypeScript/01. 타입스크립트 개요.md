# 타입스크립트란

- JavaScript에 정적 타입(static type)을 추가한 슈퍼셋(superset) 언어이다.
- 브라우저나 Node.js가 직접 실행하지 못하므로, 컴파일(tsc) 과정을 거쳐 JavaScript로 변환된다.
- 컴파일 시점에 타입을 검사하므로, 런타임에서 터지던 타입 오류를 개발 단계에서 미리 잡을 수 있다.

# 왜 쓰는가 (JavaScript 대비 장점)

- 런타임 오류를 컴파일 타임으로 앞당긴다. (가장 핵심 가치)
- IDE 자동완성과 리팩토링이 안정적이다. (타입 정보 기반)
- 타입 자체가 문서 역할을 한다. 함수의 입력/출력 계약이 명확해 협업에 유리하다.
- 대규모 코드베이스의 유지보수성이 높아진다.

# 단점

- 컴파일 단계가 추가되고 빌드 설정이 필요하다.
- 러닝커브가 있다. (제네릭, 고급 타입 등)
- `any`를 남용하면 타입 시스템이 무력화되어 TS를 쓰는 의미가 사라진다.

# JavaScript와의 관계

- 모든 유효한 JavaScript 코드는 유효한 TypeScript 코드이다. (점진적 도입 가능)
- 컴파일 결과물은 순수 JavaScript이며, 타입 정보는 런타임에 존재하지 않는다. (타입은 컴파일 후 모두 제거됨)
