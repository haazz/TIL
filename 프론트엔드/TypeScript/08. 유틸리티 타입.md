# 유틸리티 타입이란

- 기존 타입을 변형해 새 타입을 만드는, TS 내장(built-in) 타입들이다.
- DTO 변형 등에서 중복 정의 없이 타입을 재사용할 수 있어 유용하다.

# 자주 쓰는 유틸리티 타입

- `Partial<T>` : 모든 프로퍼티를 선택적(optional)으로 만든다.
- `Required<T>` : 모든 프로퍼티를 필수로 만든다.
- `Readonly<T>` : 모든 프로퍼티를 읽기 전용으로 만든다.
- `Pick<T, K>` : T에서 K 프로퍼티만 골라낸다.
- `Omit<T, K>` : T에서 K 프로퍼티를 제외한다.
- `Record<K, V>` : 키 K, 값 V를 갖는 객체 타입을 만든다.

# 예시

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

type UserUpdate = Partial<User>;          // 모든 필드 optional (수정 DTO)
type UserPreview = Pick<User, "id" | "name">; // id, name만
type UserWithoutId = Omit<User, "id">;    // id 제외
type UserMap = Record<number, User>;      // { [id: number]: User }
```

# 활용 포인트

- 생성 DTO를 정의해두고, 수정 DTO는 `Partial<CreateDto>`로 재사용하는 식으로 중복을 줄인다.
- 원본 타입이 바뀌면 파생 타입도 자동으로 따라가므로 유지보수에 강하다.
