# 대칭키 (Symmetric Key)

- 암호화와 복호화에 **같은 키**를 사용하는 방식이다.
- 빠르고 가볍다.
- 단점: 키를 상대에게 안전하게 전달하는 과정(키 교환)이 어렵다. 키가 노출되면 끝이다.
- 예: AES.

# 비대칭키 (Asymmetric Key, 공개키 암호화)

- **공개키(public key)**와 **개인키(private key)** 쌍을 사용한다.
- 공개키로 암호화하면 개인키로만 복호화할 수 있고, 그 반대도 성립한다.
- 키 교환 문제를 해결하지만 연산이 느리다.
- 예: RSA, ECC.

# HTTPS / TLS 핸드셰이크에서의 활용

- HTTPS는 둘을 조합해 "안전한 키 교환 + 빠른 통신"을 모두 얻는다.

1. 서버가 **인증서(공개키 포함)**를 제시하고, 클라이언트는 CA를 통해 신뢰를 검증한다.
2. **비대칭키**로 통신에 쓸 **대칭키(세션 키)**를 안전하게 교환한다.
3. 이후 실제 데이터 통신은 빠른 **대칭키**로 암호화한다.

- 정리: **신원 확인 + 키 교환 = 비대칭키 / 실제 데이터 암호화 = 대칭키**

# 전자서명에서의 활용

- 개인키로 서명하고 공개키로 검증하면, 보낸 사람이 맞고(인증) 내용이 위변조되지 않았음(무결성)을 보장한다.
- 참고: JWT의 서명도 이 원리(HMAC 대칭 또는 RSA 비대칭)를 사용하며, 이는 "암호화"가 아니라 "서명"이다.
