# CORS (Cross-Origin Resource Sharing)란

- 다른 출처(origin)의 리소스에 접근할 때 적용되는 브라우저의 보안 정책이다.
- 출처(origin) = 프로토콜 + 도메인 + 포트. 셋 중 하나라도 다르면 교차 출처(cross-origin)이다.

# 왜 발생하는가

- 브라우저에는 **SOP(동일 출처 정책, Same-Origin Policy)**가 있어, 기본적으로 다른 출처로의 요청 응답을 차단한다.
- 이는 악성 사이트가 사용자의 인증 정보로 다른 사이트 API를 함부로 호출하는 것을 막기 위한 보안 장치이다.
- 서버가 "이 출처는 허용한다"는 응답 헤더를 주지 않으면 브라우저가 응답을 막아 CORS 에러가 난다.

# 해결 방법

- 서버가 응답에 허용 헤더를 추가한다.
  - `Access-Control-Allow-Origin: https://example.com`
  - `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers` 등
- 또는 프론트와 API의 도메인을 통일하거나, 같은 출처로 보이도록 프록시를 둔다.

# 주의할 점

- CORS는 **브라우저에서만** 적용되는 정책이다.
- 서버 ↔ 서버 간 호출에는 CORS가 적용되지 않는다.
- 본격 요청 전에 브라우저가 `OPTIONS` 메서드로 사전 확인(Preflight)을 보내는 경우가 있다.
