# REST란

- 자원(Resource)을 URI로 표현하고, HTTP 메서드로 그 자원에 대한 행위를 표현하는 아키텍처 스타일이다.
- REST 원칙을 잘 지킨 API를 RESTful 하다고 한다.

# 설계 원칙

- 자원은 **명사**로 표현한다. 예: `/users`, `/users/1/orders`.
- 행위는 **HTTP 메서드**로 표현한다. (URI에 동사를 넣지 않음. `/getUser` X)
- 무상태(stateless) : 각 요청은 필요한 정보를 모두 담고, 서버는 요청 간 상태를 저장하지 않는다.
- 자원의 상태는 표현(JSON 등)으로 주고받는다.

# HTTP 메서드

- **GET** : 조회 (멱등)
- **POST** : 생성 (비멱등)
- **PUT** : 전체 수정/교체 (멱등)
- **PATCH** : 부분 수정
- **DELETE** : 삭제 (멱등)

# HTTP 상태 코드

- **2xx** : 성공 (200 OK, 201 Created, 204 No Content)
- **3xx** : 리다이렉트 (301, 302)
- **4xx** : 클라이언트 오류 (400 잘못된 요청, 401 미인증, 403 권한 없음, 404 없음, 409 충돌)
- **5xx** : 서버 오류 (500 내부 오류, 503 서비스 불가)

# 한계와 대안

- 클라이언트가 필요한 데이터보다 많이/적게 받는 over-fetching, under-fetching이 생길 수 있다.
- 이를 보완하려고 **GraphQL**(필요한 필드만 질의), **gRPC**(HTTP/2+Protobuf, 빠른 내부 통신) 등을 쓰기도 한다.
