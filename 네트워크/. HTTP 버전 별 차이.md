# HTTP/1.1

- `keep-alive`로 하나의 TCP 연결을 재사용할 수 있게 되었다. (매 요청마다 연결을 새로 맺지 않음)
- 하지만 한 연결에서 요청을 **순차적으로** 처리한다. 앞 요청이 느리면 뒤 요청이 밀리는 **HOL(Head-of-Line) 블로킹**이 발생한다.

# HTTP/2

- 하나의 연결에서 여러 요청/응답을 **동시에 주고받는 멀티플렉싱(multiplexing)**을 지원한다. (HTTP 레벨 HOL 블로킹 해소)
- 헤더를 압축(HPACK)해 오버헤드를 줄인다.
- 서버가 미리 리소스를 보내는 서버 푸시(Server Push)도 도입되었다. (현재는 사용 축소)
- 단, TCP 위에서 동작하므로 **TCP 레벨의 HOL 블로킹**은 남아 있다.

# HTTP/3

- 전송 계층을 TCP에서 **QUIC(UDP 기반)**으로 변경했다.
- 연결 수립이 빠르고(핸드셰이크 단축), 패킷 손실 시에도 다른 스트림이 막히지 않아 **TCP HOL 블로킹까지 해소**한다.
- 연결 식별을 IP가 아닌 Connection ID로 하여, 네트워크 전환(WiFi↔LTE) 시에도 연결이 유지된다.

# 정리

- 1.1 : 연결 재사용, 그러나 순차 처리(HOL 블로킹)
- 2 : 멀티플렉싱 + 헤더 압축 (TCP 한계는 남음)
- 3 : QUIC(UDP)로 전송 계층 교체, HOL 블로킹 근본 해소
